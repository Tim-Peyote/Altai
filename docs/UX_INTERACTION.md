# Altai — UX, интерфейс и взаимодействия

Целевые требования, актуализированы 8 сентября 2026. Это не перечень реализованных экранов. Объём и спорные решения определяет [GAME_DESIGN](GAME_DESIGN.md); стиль — [UI_STYLE_GUIDE](UI_STYLE_GUIDE.md).

## 1. Принципы UX

1. Мир сообщает первым, интерфейс подтверждает вторым.
2. Одна кнопка означает один устойчивый тип намерения во всей игре.
3. Важная информация имеет минимум два канала: визуальный + звук/текст/тактильный cue.
4. Психоделический стиль никогда не скрывает обязательную gameplay-информацию без доступной альтернативы.
5. Игрок может остановить одиночную игру в любой момент через обычную паузу.
6. Частые действия короткие; редкие важные действия получают физическую анимацию и вес.

## 2. Главное меню

Главное меню — живая сцена дорожного лагеря: персонаж у костровища, полевая лаборатория, природный фон. Камера почти неподвижна, пункты аккуратно встроены поверх сцены. Установленные улучшения лаборатории видны в композиции; это не закрытая комната с окном. До первой находки используется нейтральный природный фон без принадлежащей герою лаборатории и без будущих приборов.

Пункты:

- **Продолжить** — последнее выбранное прохождение;
- **Новая игра** — имя и создание отдельного прохождения без перезаписи существующих;
- **Загрузить игру** — список прохождений: имя, время игры, дата последнего сохранения;
- **Настройки**;
- **Авторы**;
- **Выйти**.

Без читаемого прохождения `Продолжить` и `Загрузить игру` недоступны. После начала кампании стол меняется: появляются реальные найденные предметы, записи и следы состояния леса. Меню тем самым напоминает о незавершённых вопросах без рекламных баннеров.

Модель записей и правила выхода: [SAVE_PROFILES](SAVE_PROFILES.md).

### Первый запуск

До начала игры показываются:

- язык;
- яркость с различимыми контрольными символами;
- общий visual intensity: полный / мягкий / минимальный;
- предупреждение о вспышках и движении изображения;
- выбор мышь/геймпад без фиксации метода ввода.

## 3. Pause menu

- Продолжить
- Журнал текущей вылазки
- Настройки
- Управление
- Сохранить и выйти в главное меню
- Выйти из игры без нового сохранения — с подтверждением потери изменений после последней записи; ранее сделанные автосохранения остаются.

Обычная пауза полностью останавливает мир, звук переводится в Pause snapshot. Нельзя использовать pause menu как безопасный инвентарь: предметы там не меняются.

## 4. HUD

Постоянный HUD минимален:

- маленькая точка/скобка фокуса в центре;
- короткий prompt взаимодействия только при наличии цели;
- ненавязчивый индикатор занятой руки;
- физиологические состояния появляются только при изменении или опасном уровне;
- текущая цель кратко показывается после выхода/обновления и затем скрывается.

На экране постоянно нет:

- обязательной неотключаемой миникарты (компактная миникарта допускается настройкой);
- полосы опыта;
- списка всех заданий;
- числовой шкалы голода;
- рамки активного квеста;
- подписей над каждым собираемым объектом.

Состояния передаются комбинацией анимации рук, дыхания, звука, краёв изображения и доступного по кнопке краткого status panel. Для доступности любой канал можно продублировать иконкой/текстом.

## 5. Единый язык взаимодействия

Базовые намерения:

- **Primary / короткое нажатие** — выполнить очевидное обратимое действие: взять, открыть, положить.
- **Primary / удержание** — длительное или опасное действие: срезать, выпить, разлить, разобрать.
- **Secondary** — альтернативное действие с предметом или отмена текущего размещения.
- **Inspect** — приблизить предмет и перейти к осмотру признаков.
- **Use tool** — применить предмет в активной руке.
- **Radial/quick access** — выбрать подготовленный инструмент без открытия сумки.
- **Back** — отмена до момента необратимого результата.

Prompt строится как `глагол + объект`, например:

- `Взять: стеклянная колба`
- `Удерживать: срезать шляпку`
- `Перемешать содержимое`

Название неизвестного объекта не раскрывается: `Осмотреть неизвестный гриб`, пока игрок не подтвердил вид.

### Приоритет цели под взглядом

1. предмет в прямой видимости и в зоне рук;
2. активная часть станции;
3. крупный объект окружения;
4. дальний информационный осмотр.

Переключение фокуса имеет небольшую задержку, чтобы prompt не дрожал между близкими объектами. Объект не получает яркую универсальную обводку; используются лёгкий rim, изменение reticle и звук фокуса. High-contrast outline доступен настройкой.

## 6. Предмет в руках

Игрок имеет две логические руки, но управление остаётся простым:

- основная рука держит инструмент или активный предмет;
- вспомогательная участвует в анимации, поддерживает сосуд или карту;
- тяжёлый объект занимает обе руки;
- новый предмет сначала появляется в руке, затем по команде отправляется в сумку;
- если руки заняты, игра предлагает убрать текущий предмет, а не молча заменяет его.

Viewmodel рук не определяет положение gameplay-коллизии. Мир и анимация рук синхронизируются через события, но authoritative interaction остаётся в world model.

## 7. Сумка и быстрый доступ

Сумка — компактный пространственный экран, открываемый поверх мира. Единое рабочее правило первого прототипа: сумка и карта по умолчанию приостанавливают одиночную игру. Физическая работа на станции идёт в мире; отдельная Pause-команда всегда доступна. Альтернативный режим без паузы или с замедлением можно оценить после плейтеста.

Основное представление — сетка предметов и фильтры слева, вращаемый персонаж с ячейками снаряжения в центре, описание и действия справа. Общие вкладки «Инвентарь» и «Карта» находятся сверху слева. Физические зоны сумки могут дополнить её позднее, но не являются отдельной обязательной системой:

- места быстрого доступа для инструментов;
- защищённые ячейки для сосудов;
- общий объём для образцов;
- карман для карты и записей.

Игрок видит:

- размер и состояние предмета;
- свежесть качественными стадиями, а не точным процентом до изучения;
- загрязнение/повреждение;
- число доз для тары.

Основные действия доступны без контекстного лабиринта: взять в руку, осмотреть, переместить, выбросить. Употребление требует удержания и подтверждается физическим действием.

## 8. Карта и навигация

Карта открывается на M и показывает только исследованные участки, сохраняя прогресс отдельно для варианта мира. Подача напоминает полевую карту; обязательная анимация бумажного предмета в руках не требуется. Она показывает:

- постоянную географию;
- подтверждённые ориентиры;
- собственные условные знаки игрока;
- область цели, если она известна по записи;
- степень достоверности старых отметок исследователя.

Положение и направление игрока читаются на карте; неопознанные POI и ресурсы не раскрываются автоматически. Компактную миникарту можно отключить. Игрок также ориентируется по рельефу и компасу, но отсутствие стрелки не является обязательным ограничением.

Метки в мире делаются ограниченным физическим ресурсом либо запоминаются как landmark после внимательного осмотра. Нельзя расставить сотню HUD-точек.

## 9. Гербарий и доска расследования

Гербарий отвечает на вопрос «что я знаю?», доска — «что я хочу проверить дальше?».

### Страница объекта

- рисунок/фотография изученных частей;
- наблюдаемые признаки;
- места и условия встреч;
- известные способы обработки;
- подтверждённые эффекты;
- опасные сходные виды;
- связанные гипотезы и рецепты.

Неизвестные данные показаны конкретными вопросами, например `реакция на нагрев не проверена`, а не сеткой из 12 замков.

### Доска

Игрок закрепляет одну основную и одну побочную гипотезу. Карточка гипотезы содержит:

- что требуется проверить;
- какие признаки уже известны;
- примерные условия;
- что взять с собой;
- поле для пользовательской метки.

На HUD не остаётся checklist. При необходимости цель вспоминается через короткую запись или физический блокнот.

## 10. Интерфейс сбора растения

Сбор имеет три стадии:

1. **Осмотр** — вращение взгляда/предмета, лупа, признаки и сравнение с гербарием.
2. **Выбор** — целая особь, шляпка, ножка, корень, ягоды, споры; доступно не для всех видов.
3. **Действие** — сорвать, срезать, выкопать, стряхнуть, взять пробу.

Игра показывает ожидаемый тип результата, но не скрытые химические свойства. Неподходящий инструмент визуально повреждает образец; это не случайный штраф после завершения.

После частого успешного сбора знакомого вида анимация становится короче, но решение о части растения сохраняется, если оно значимо.

## 11. Интерфейс готовки

### Первая найденная лаборатория

Первый маршрут приводит к базовому полевому очагу. Игрок осматривает находку, получает доступ к простому комплекту и готовит первый состав. До находки лабораторию нельзя вызвать. Неустановленные приборы не работают и не изображаются доступными; сложный рецепт объясняет, какое улучшение требуется. Первый переход не требует позднего прибора.

### Режим станции

При приближении игрок видит обычный мир. После взаимодействия камера мягко фиксируется в рабочей зоне, освобождая точный курсор/прицел для инструментов. Выйти можно в любой момент, кроме короткой фазы необратимого переливания.

Рабочая поверхность разделена физически:

- сырьё;
- подготовка;
- нагрев;
- фильтрация/перегонка;
- готовая тара;
- книга рецептов на подставке.

### Помощь без автопрохождения

Рецепт можно прикрепить открытым рядом. Он использует наблюдаемые формулировки:

- `измельчить до крупной влажной крошки`;
- `держать ниже бурного кипения`;
- `снять после третьего потемнения пара`.

После освоения рядом появляются уточнения, добытые игроком: допустимый диапазон, подходящая часть, известная несовместимость.

### Feedback

- инструмент подсвечивает доступную точку применения;
- анимация руки предварительно показывает действие до отпускания;
- температура видна по жидкости, пару, звуку и прибору, если он открыт;
- завершённая фаза отмечается физическим изменением, а не всплывающей галочкой;
- критическая ошибка имеет короткое окно исправления, если это логично.

### Recipe history

После разлива сохраняется журнал процесса: не сырые числа, а понятные факты (`перегрето после добавления корня`, `осадок не удалён`). Это позволяет учиться и сравнивать попытки.

## 12. Диалоги, кассеты и текст

- разговоры по радио не блокируют движение, если не требуют выбора;
- кассету можно слушать во время работы в убежище;
- важные записи имеют субтитры и текстовую расшифровку;
- длинная экспозиция разбивается действиями и наблюдаемыми изменениями;
- найденная запись сначала отвечает на локальный вопрос, затем создаёт новый.

## 13. Звук как интерфейс

Звук — gameplay-канал, а не украшение.

Основные категории:

- **foley игрока** — поверхность, одежда, дыхание, работа руками;
- **объектный звук** — кипение, стекло, нож, ступка, механизмы;
- **экология** — слои биома, время суток, погода;
- **угрозы** — читаемые паттерны расстояния и состояния;
- **восприятие** — tinnitus, фильтрация, whispers, pitch/time distortion;
- **музыка** — редкая, преимущественно переходы и смысловые пики.

Spatial audio используется для навигации и угроз. Критичный cue не маскируется музыкой: AudioDirector управляет приоритетом и sidechain/ducking через шины.

Предлагаемые шины:

```text
Master
├── Music
├── UI
├── PlayerFoley
├── World
│   ├── Ambience
│   ├── Creatures
│   └── Interactions
├── Voice
└── Perception
```

Настройки имеют отдельные уровни для master, music, ambience, effects и voice. Dynamic range: night / normal / wide. Для ключевых направленных звуков доступен визуальный индикатор, не раскрывающий точное положение угрозы.

## 14. 3D-визуал как интерфейс

Визуальный язык делится на три слоя:

- **world truth** — геометрия, материалы, свет, физическое состояние предметов;
- **perception** — изменения объектов, доступных маршрутов и существ;
- **lens** — сдержанная постобработка и регулируемые эффекты восприятия, без обязательной VHS/PS1-стилизации.

Gameplay-признак нельзя передавать только lens-эффектом. Например, активный грибной мост существует как геометрия/коллизия мира; shader лишь усиливает его состояние.

Важные материалы имеют читаемый силуэт и тональный контраст. Свет направляет внимание, но не заменяет взаимодействие. Туман создаёт глубину; локальные объёмы тумана описывают природные зоны, а не случайно закрывают цель.

## 15. Visual settings и доступность

### Presets

- **Полный** — авторская метаморфоза и пространственные эффекты в пределах настроек доступности.
- **Мягкий** — сохранены атмосфера и смысл, снижены движение камеры, вспышки и двоение.
- **Минимальный** — почти стабильное изображение, gameplay-состояния передаются геометрией, цветом, UI и звуком.

### Независимые настройки

- camera shake;
- head bob;
- field of view;
- motion blur;
- chromatic aberration;
- flashes;
- hallucination motion;
- reticle size/contrast;
- subtitles, speaker names and background;
- hold/toggle для приседания, бега, осмотра и взаимодействия;
- пауза сумки и карты по умолчанию; альтернативный темп мира — после проверки прототипа;
- цветовые фильтры и дублирующие символы.

## 16. Controller и мышь

Все экраны полностью управляются обоими методами. Последний использованный input device меняет подсказки мгновенно.

Геймпад:

- магнитный focus только для мелких объектов в пределах малого угла;
- регулируемые inner/outer deadzone и response curve;
- отдельная чувствительность осмотра предмета;
- radial quick access с замедлением мира по настройке.

Мышь:

- raw input;
- отдельная чувствительность обычного взгляда и station mode;
- отсутствие ускорения по умолчанию.

## 17. UX-flow vertical slice

```text
Главное меню с дорожным лагерем
  → Новая игра в Яви / продолжение сохранённой сессии
  → Ориентир, след экспедиции, гипотеза, сбор
  → Находка базовой лаборатории-очага на первом маршруте / возвращение к ней
  → Выбор образца, приготовление, получение предмета
  → Применение и проверка гипотезы / метаморфоза
  → Новая информация, улучшение приборов, решение идти дальше или закрепить знание
  → Продолжение / новая вылазка с сохранённой метапрогрессией
```

Каждый переход должен отвечать игроку на два вопроса: `что изменилось?` и `что я теперь хочу проверить?`.

## 18. UX Definition of Done

Новая механика готова, если:

- игрок понимает доступное действие без постоянной подписи;
- управление одинаково трактуется мышью и геймпадом;
- есть anticipation, результат и feedback отмены/ошибки;
- критичное состояние сообщается минимум двумя каналами;
- экранные эффекты можно снизить без потери правила;
- prompt использует тот же глагол, что гербарий и tutorial;
- интерфейс корректно работает при длинной локализации;
- действие проверено на незнакомом с проектом игроке.
