# Altai — архитектура и визуальная работа в Unreal Engine

Редакция 8 сентября 2026. Сверка с руководствами Epic и установленным UE 5.8.2. Это проект технического решения, а не отчёт о созданных классах и ассетах. Первый каркас из пяти модулей, двух карт и базовых экранов уже создан; точный состав реализации — в [PROTOTYPE_STATUS](PROTOTYPE_STATUS.md). Остальные уровни и системы ниже остаются проектом.

Документ конкретизирует [MODULAR_ARCHITECTURE](MODULAR_ARCHITECTURE.md). Устройство лаборатории остаётся открытым: исходная идея — найти первый базовый очаг и постепенно улучшать оснащение. Перенос, проявление, число очагов и связь с возвращением после поражения пока не закрепляются архитектурой.

## 1. Что в Unreal называется сценой

В UE нет одного универсального типа scene для всех задач. Для Altai выбираем несколько нативных форматов. Названия ниже — предлагаемые имена будущих ассетов.

| Что открывает автор | Формат UE | Что видно и редактируется |
|---|---|---|
| Долина Яви `L_Yav` | Level / Map, `.umap` | Рельеф, объекты, свет, вода, маршруты, звук, размещённые композиции |
| Мицелиальный хор `L_Choir` | Отдельный Level / Map | Собственное окружение; можно работать, не проходя переход из Яви |
| Фон меню `L_Frontend` | Level | Камера, окружение и визуальное представление выбранного сохранения |
| Лагерь или пещера `LI_ExpeditionCamp` | Исходный Level + Level Instance в регионе | Группа отдельных акторов: реквизит, свет, локальные звуки, точки взаимодействия |
| Игрок `BP_AltaiCharacter` | Actor Blueprint на базе Character | 3D Viewport, дерево компонентов, тело, камеры, точки крепления |
| Котёл `BP_Station_Cauldron` | Actor Blueprint | Модель, локальные компоненты, точки работы рук, VFX, Audio Component |
| Сумка `WBP_Inventory` | Widget Blueprint | UMG Designer: иерархия, сетка, карточки, отступы, фокус, анимации |
| Погода `BP_WeatherRig` | Actor Blueprint + профили данных | Видимые компоненты осадков и параметры; окружение проверяется в уровне |
| Переход `LS_YavToChoir` | Level Sequence | Дорожки камеры, света, звука и эффектов в Sequencer |
| Звук котла `MS_Cauldron` | MetaSound Source | Звуковой граф, входные параметры, прослушивание |
| Испытательный стенд `L_Preview_Stations` | Обычный отдельный Level | Несколько приборов в масштабе, свет, тестовый игрок и управляемые состояния |

Level Instance позволяет многократно размещать композицию из исходного уровня и редактировать её с сохранением изменений в источник. Blueprint Viewport позволяет двигать компоненты объекта. В UMG отдельный Designer предназначен для визуальной компоновки экрана. Это разные редакторы, поэтому слово «сцена» в постановке всегда сопровождается типом ассета. Источники: [Level Instancing](https://dev.epicgames.com/documentation/en-us/unreal-engine/level-instancing-in-unreal-engine), [Blueprint Viewport — справка интерфейса 4.27](https://dev.epicgames.com/documentation/en-us/unreal-engine/blueprint-editor-viewport?application_version=4.27), [Widget Blueprints — UE 5.8](https://dev.epicgames.com/documentation/en-us/unreal-engine/widget-blueprints-in-umg-for-unreal-engine). Старую страницу Viewport используем только для базового принципа, доступность конкретных операций проверяем в 5.8.2.

**Практическое требование:** двойной щелчок по ассету открывает его собственный редактор. Для составной 3D-композиции можно открыть исходную карту и свободно перемещать камеру; для отдельного прибора — его Blueprint Viewport. Поведение во времени, физика и взаимодействие проверяются через Play/Simulate на отдельном стенде. Простое открытие Blueprint не запускает полноценную игровую сессию.

Изменение исходного Blueprint применяется к его экземплярам с учётом явно заданных локальных переопределений. Изменение одного экземпляра в уровне не означает автоматического изменения всех остальных. Для общих правок автор открывает исходный ассет.

## 2. Граница визуальной сборки и кода

Авторские композиции сохраняются в `.umap` и `.uasset`. Модели, относительное расположение, источники света и звука, рабочие точки приборов существуют до нажатия Play. C++ задаёт правила и базовые компоненты, Blueprint и специализированные редакторы — состав и настраиваемое представление.

Правила Altai:

- `BeginPlay` не строит с нуля меню, очаг и всё окружение из координат в коде.
- Construction Script допустим для небольших предсказуемых зависимостей и предпросмотра. Он не удаляет ручную композицию, не читает сохранение и не выдаёт игровые предметы при перемещении объекта в редакторе.
- Общая логика не живёт в Level Blueprint. Там допускается минимальная локальная постановка; повторно используемые процессы принадлежат системам и компонентам.
- Скрипт редактора или MCP может однажды создать исходный ассет. После сохранения он открывается и редактируется без повторного запуска этого скрипта. Повторная генерация не перезаписывает правки автора без отдельного действия.
- Динамически появляются только экземпляры готовых классов и контента: предметы, живые существа, участки процедурного наполнения. Их образцы также открываются отдельно.
- C++-корень обеспечивает идентичность и правила объекта; художественная часть остаётся доступной для редактирования в дочернем Blueprint. Не закреплять всю визуальную иерархию неизменяемыми приватными компонентами.

Blueprint-граф тоже является программной логикой. Цель — доступный визуальный монтаж и настройка контента при устойчивых правилах, а не отсутствие кода как такового.

## 3. Модули сборки и игровые области

Модуль UE — единица кода с зависимостями и `Build.cs`, а папка Content — организация ассетов. Плагин может содержать модули и контент. Ни папка, ни Level не заменяют границу ответственности кода. Основа: [Unreal Engine Modules](https://dev.epicgames.com/documentation/en-us/unreal-engine/unreal-engine-modules).

Предлагаемая начальная структура зависимостей (стрелка означает «зависит от»):

```text
AltaiCore                         — ID, контракты, определения и структуры состояния
AltaiGameplay     → AltaiCore      — игровые правила и компоненты
AltaiPresentation → AltaiCore      — UI, аудио, визуальное представление через контракты
Altai             → все три       — основной модуль, сборка зависимостей и запуск
AltaiEditor       → runtime       — редакторские проверки, предпросмотр и инструменты
```

Это пять предлагаемых C++-модулей, а не пять гигантских классов. В `AltaiGameplay` отдельные области Player, Items, Interaction, Cooking, Stations, World, Weather, Narrative, Fauna, Persistence и Flows. При реальной необходимости область можно вынести в самостоятельный модуль позднее. Редакторский код не подключается к игровым модулям; зависимости циклов не образуют.

`AltaiCore` не хранит изменяемый глобальный мир. Он задаёт общие типы и интерфейсы. Владельцы живого состояния находятся в Gameplay. Presentation получает снимки и события через эти интерфейсы; основной модуль связывает реализации. Не строить отдельную универсальную систему внедрения зависимостей ради этого проекта.

Папки ассетов группируются по работе автора:

```text
Content/Altai/
  Frontend/Maps, UI
  Player/Blueprints, Animation, Input
  World/Yav, Choir, Shared
  POI/ExpeditionCamp, CaveEntrance
  Stations/Shared, Cauldron, Mortar, Hearth
  Items/Definitions, Visuals
  Cooking/Recipes
  Narrative/Data, Sequences
  Environment/Weather, Lighting, VFX
  Audio/Sources, MetaSounds, Attenuation, Concurrency, Mix
  UI/HUD, Inventory, Journal, Map, Shared
  Dev/Maps, Fixtures
```

Пути здесь обозначают будущие группы; ассеты стендов исключаются из состава выпуска. Плагин All Toolsets для MCP не является архитектурой игровых модулей.

## 4. Кто живёт сколько и чем владеет

GameInstance сохраняется между загрузками уровней; GameMode создаётся для загруженного мира. Subsystems получают жизненный цикл от своего владельца. Это основа распределения, а не повод помещать всё в GameInstance. Источники: [Gameplay Framework](https://dev.epicgames.com/documentation/en-us/unreal-engine/gameplay-framework-in-unreal-engine), [Subsystems](https://dev.epicgames.com/documentation/en-us/unreal-engine/programming-subsystems-in-unreal-engine). Для `UWorldSubsystem` дополнительно проверен заголовок установленного UE: `Engine/Source/Runtime/Engine/Public/Subsystems/WorldSubsystem.h`.

| Владелец в Altai | Предлагаемая реализация | Состояние и срок жизни |
|---|---|---|
| Запуск и завершение экспедиции | `UGameInstanceSubsystem` | Создаёт явную сессию, закрывает её при возврате в меню; subsystem продолжает жить |
| Сессия экспедиции | `UObject`, удерживаемый subsystem | ID, seed, реестр изменений мира, владельцы знаний и предметов; переживает загрузку карт |
| Знания, предметы, партии | Отдельные объекты-владельцы внутри сессии | Единственные изменяемые записи; загруженные акторы связываются с ними по ID |
| Правила входа в карту | Отдельные `GameModeBase` для Frontend, Expedition и Preview | Выбор Pawn/Controller, настройка текущего мира; не архив кампании |
| Регион и его загрузка | `UWorldSubsystem` | Загруженные участки и регистрации акторов текущего мира |
| Время и погода | Состояние в сессии + исполнитель текущего мира | Симуляция условий; свет и звук читают результат |
| Игрок | `Character`, `CharacterMovement`, компоненты | Перемещение и активный организм; снимок при смене карты восстанавливается в новом акторе |
| Управление и камеры | `PlayerController`, `PlayerCameraManager`, Enhanced Input | Управление одним телом, разрешённые режимы камеры и ввода |
| Станция или контейнер в сцене | Actor + компоненты взаимодействия и представления | Ссылается на запись сессии; выгрузка Actor не уничтожает содержимое и партию |
| UI пользователя | `ULocalPlayerSubsystem` + отдельные Widgets | Стек экранов, фокус, подписки на текущую сессию |
| Звук текущего мира | Аудиокоординатор уровня мира + локальные Audio Components | Контролируемые источники и переходы; очистка при закрытии мира |
| Настройки громкости | Постоянные пользовательские настройки | Не зависят от текущего региона или звукового компонента |
| Запись на диск | `UGameInstanceSubsystem` + SaveGame-объекты | Версия формата, очередь записи, восстановление; не второй инвентарь |

Физическая сцена сессии в прошлой схеме была слишком общим термином. В UE визуально открывается карта, а сессия соединяет её с состоянием игры. Для обозримости в карте будет `BP_WorldPresentationRoot` с явными ссылками на свет, погоду и акустические профили. Он не управляет предметами и повествованием.

Subsystems для runtime фильтруют тип мира и режим работы. Открытие редактора Blueprint или preview-карты не запускает настоящую экспедицию. `Initialize` создаёт инфраструктуру, но готовность карты и игрока подтверждается отдельно. Не предполагать, что порядок `BeginPlay` произвольных акторов совпадёт с нужным порядком запуска.

## 5. Оркестраторы

«Оркестратор» — наша роль в архитектуре, а не специальный обязательный класс UE. Для Altai это небольшой объект процесса с явными стадиями, владельцем и правилами отмены. Диагностика показывает стадию, ожидаемого участника и последнюю ошибку.

| Процесс | Где живёт | Что согласует |
|---|---|---|
| `SessionFlow` | GameInstance subsystem | Меню → создание/чтение сессии → загрузка карты → восстановление → управление; обратный путь и очистка |
| `InteractionFlow` | Компонент взаимодействия игрока | Цель → допустимость → подготовка → одно подтверждение → завершение/отмена |
| `WorldTransitionFlow` | Объект в сессии | Подготовка нового слоя, расход состава, безопасность игрока, смена представления, завершение |
| `SaveLoadFlow` | Subsystem сохранения | Согласованный снимок всех владельцев → запись → подтверждение; восстановление по версиям |
| `AudioSceneFlow` | Аудиокоординатор мира | Плавная смена ambience и микса при входе, выходе, паузе и переходе |

Перенос предмета — атомарная команда владельцу предметов. Ему не нужен отдельный глобальный «оркестратор инвентаря». Готовка владеет своей машиной состояний партии. Анимационный контакт может запросить подтверждение операции с ID, но не списывает сырьё самостоятельно.

Оркестратор развёртывания лаборатории **не создаётся до решения её дизайна**. У станций пока достаточно контрактов доступности операции, рабочих точек, контейнеров и улучшений. Один такой прибор позже можно поставить в постоянный очаг или включить в переносную композицию.

Для длительных процессов: timeout, отмена, однократный commit и восстановление после загрузки. Ни завершение звука, ни финальный кадр Sequencer не являются единственным доказательством успешного перехода. Простой процесс достаточно выразить enum и методами перехода; StateTree вводится там, где действительно улучшает авторскую работу.

## 6. Уровни, слои и генерация

World Partition управляет загрузкой пространственных ячеек; Data Layers организуют наборы акторов и их состояния загрузки. Они не создают автоматически географию и не являются восемью сюжетными мирами. Источники: [World Partition](https://dev.epicgames.com/documentation/en-us/unreal-engine/world-partition-in-unreal-engine), [Data Layers](https://dev.epicgames.com/documentation/en-us/unreal-engine/world-partition---data-layers-in-unreal-engine).

Предложение для первого каркаса: отдельные карты Яви и Хора с отдельно открываемыми POI. Выбор между сменой карт и совместной потоковой загрузкой для метаморфозы принять после технического стенда. Data Layers подходят для вариантов одной области; загружать восемь полных миров одновременно не требуется. World Partition включать на картах регионов при подтверждённой потребности; маленьким стендам и фону меню он не обязателен.

Для новых вариантов экспедиции отдельно проектируется генерация плана региона. PCG используем для управляемого наполнения по поверхностям, маскам, сплайнам и исключениям. PCG имеет собственный редактор графа и предпросмотр, но сам по себе не гарантирует связный водосбор, сюжет или произвольную перестройку Landscape во время игры. Источник: [PCG Overview](https://dev.epicgames.com/documentation/en-us/unreal-engine/procedural-content-generation-overview).

Авторские опоры и POI хранятся отдельно от генерируемого наполнения. В редакторе явно различимы Authored, Generated и Debug; это организационные группы, а не обязательные три Data Layer. Регенерация очищает только принадлежащий генератору результат. Добыча и изменения сохраняются по ID независимо от наличия актора в памяти.

Packed Level Blueprint предназначаем для оптимизации статических композиций после проверки. Рабочую станцию с контейнерами и поведением не превращаем ради оптимизации в неразделимый статический объект.

## 7. Звук: самостоятельная авторская система

Встроенного аудиостека UE достаточно для первой реализации; необходимость внешнего middleware сейчас не установлена. Звуки существуют как отдельные ассеты и видимые компоненты сцены. `PlaySound` удобен для коротких одноразовых событий; управляемому длительному источнику нужен доступный Audio Component. Источник: [Audio Engine Overview](https://dev.epicgames.com/documentation/en-us/unreal-engine/audio-engine-overview-in-unreal-engine).

| Задача | Средство UE | Решение для Altai |
|---|---|---|
| Исходные записи | Sound Wave | Вода, лес, шаги, стекло, голос; единые имена, лицензии и уровни подготовки |
| Живой звук объекта | MetaSound Source, при необходимости простой Sound Cue | Костёр, котёл и ветер с управляемыми параметрами; не требуется синтезировать всё с нуля |
| Положение и управление | Audio Component на Actor/Blueprint | Прикрепить к котлу или существу; плавно менять параметры, запускать и останавливать |
| Дистанция и препятствия | Sound Attenuation | Радиус, кривая затухания, пространственность и occlusion для конкретного семейства |
| Одновременные источники | Sound Concurrency | Лимит и правила вытеснения; не допускать сотни одинаковых петель |
| Акустика места | Audio Volume + reverb и настройки интерьера | Пещера, укрытие, открытое место; проверка на акустическом стенде |
| Группы пользовательских настроек | Sound Classes | UI, Music, Voice, Player, World, Perception |
| Обработка потока звука | Sound Submix | Реверберация, фильтрация и другая DSP-обработка по нужным маршрутам |
| Изменения микса | Audio Modulation / Control Buses и Bus Mixes | Отдельные параметры пользовательской громкости, паузы, угрозы и восприятия |

MetaSound — визуально редактируемый звуковой граф с параметрами и предпросмотром; он может работать с записями, а не только синтезом. Для начала: `MS_Hearth`, `MS_Cauldron`, `MS_Wind` и отдельные источники улик. Источник: [Epic: MetaSounds, пример и редактор](https://dev.epicgames.com/documentation/unreal-engine/7-16-metasounds).

Пространственное затухание, occlusion и реверберация требуют настройки; стандартная трассировка occlusion не моделирует физически точное распространение эха по всем ходам пещеры. Сюжетное эхо Хора проектируем как явные источники и закономерности. Источники: [Sound Attenuation](https://dev.epicgames.com/documentation/en-us/unreal-engine/sound-attenuation-in-unreal-engine), [Audio Volumes](https://dev.epicgames.com/documentation/en-us/unreal-engine/audio-volumes-in-unreal-engine).

Sound Classes, Submixes и Control Buses решают разные задачи. Не копируем старую абстрактную схему «шин» в три одинаковых дерева. Сначала назначаем категории пользовательских регуляторов, затем необходимые маршруты DSP и параметры динамического микса. У каждого регулятора один назначенный слой управления. Источники: [Submixes](https://dev.epicgames.com/documentation/en-us/unreal-engine/overview-of-submixes-in-unreal-engine), [Audio Modulation](https://dev.epicgames.com/documentation/en-us/unreal-engine/audio-modulation-overview-in-unreal-engine).

Пример связи: Cooking сообщает фактическую интенсивность кипения → представление котла передаёт `BoilIntensity` своему MetaSound → слышимый звук меняется. Звуковой граф не рассчитывает готовность состава. Пример шагов: анимационный контакт стопы + определённая поверхность выбирают звук; факт движения задаётся CharacterMovement.

Постоянный ветер принадлежит окружению, котёл — своему актору, музыка перехода — процессу перехода. При выгрузке источник останавливается или передаётся согласованному владельцу. Тишина вне слышимости не равна удалению состояния; виртуализацию и возобновление длительных источников проверяем отдельно. Concurrency дополняет правильный жизненный цикл, а не исправляет бесконечный запуск звука на Tick. Источник: [Sound Concurrency](https://dev.epicgames.com/documentation/en-us/unreal-engine/sound-concurrency-reference-guide).

Игровой слух животных — отдельные события для системы восприятия ИИ. Неслышимый из-за пользовательской громкости сигнал не должен переставать привлекать зверя. Субтитры и визуальная поддержка значимых звуков исходят из того же смыслового события, что звук. Пауза отдельно согласует мир, звуковые петли, музыку и UI-звуки; её поведение не считается автоматически решённым одной кнопкой Pause.

На `L_Preview_Audio` автор расставляет источники и объёмы, слушает переходы, меняет расстояние, погоду и интенсивность восприятия. Отдельно проверяются наушники, стереоколонки, первое/третье лицо, пауза и возвращение в меню. Положение слушателя при смене камеры требует осознанного выбора и проверки, чтобы звук у тела не «уезжал» вместе с далёкой камерой.

## 8. Остальные системы

| Область | Нативная опора | Правило проекта |
|---|---|---|
| Ввод | Enhanced Input: Actions и Mapping Contexts | Отдельные контексты Exploration, UI, Station; приоритет и отмена задаются явно |
| Анимация | Animation Blueprint, Montage, при необходимости Control Rig | Визуально редактируемое поведение тела; одна игровая экипировка и источник фактов перемещения |
| Постановка | Level Sequence / Sequencer | Камеры и эффектные последовательности отдельно; воспроизведение на стенде без изменения прогрессии |
| Предметы и рецепты | Data Assets / Primary Data Assets | Паспорт контента неизменяем во время использования экземпляра; мягкие ссылки и загрузка нужных ресурсов |
| Сохранение | SaveGame + асинхронные операции | Снимки состояния, версия генератора, резервная копия и согласование транзакций — наша ответственность |
| Фауна | AIController, Perception, Navigation, Behaviour Tree или StateTree | Поведение отдельно от рига и материалов; средство выбирается по сложности конкретного поведения |
| Свет и погода | Размещённые источники света, атмосферные компоненты, материалы и Niagara | Симуляция времени/погоды отдельно; авторские профили доступны через Details и стенд |

Enhanced Input даёт контекстные раскладки, но обработчики всё равно должны предотвращать повторное применение одного действия. Источник: [Enhanced Input](https://dev.epicgames.com/documentation/en-us/unreal-engine/enhanced-input-in-unreal-engine).

Animation Blueprint имеет собственный редактор; Sequencer — временную шкалу постановки. Их можно настраивать отдельно от правил предметов. Источники: [Animation Blueprints](https://dev.epicgames.com/documentation/en-us/unreal-engine/animation-blueprints-in-unreal-engine), [Sequencer](https://dev.epicgames.com/documentation/en-us/unreal-engine/sequencer-cinematic-editor-unreal-engine).

Primary Data Asset поддерживает идентификацию и управление загрузкой через Asset Manager; GUID экземпляра в сохранении — отдельное понятие. SaveGame не сохраняет автоматически весь мир и не обеспечивает прикладную атомарность расхода/перехода. Источники: [Data Assets](https://dev.epicgames.com/documentation/en-us/unreal-engine/data-assets-in-unreal-engine), [Saving and Loading](https://dev.epicgames.com/documentation/en-us/unreal-engine/saving-and-loading-your-game-in-unreal-engine).

Выбор Lumen, Nanite, сложных отражений и плотности растительности требует бюджета на конкретном оборудовании и платформе. В эту сверку не входит подтверждение производительности или поддержка всех эффектов на текущем Mac. MCP помогает редактировать ассеты, но не заменяет импорт качественного контента и измерения.

## 9. Проверка того, что визуальное редактирование действительно работает

Первый архитектурный этап принимается по действиям автора, а не по количеству папок:

1. Открыть `L_Frontend` и обе карты миров без запуска кампании. Увидеть их сохранённый состав в Outliner.
2. Открыть исходный POI отдельно; передвинуть реквизит и источник звука. Сохранить и увидеть изменение в его Level Instance.
3. Открыть `BP_Station_Cauldron`; сменить модель, положение рабочей точки и звуковой ресурс. На стенде проверить сохранение контракта взаимодействия.
4. Открыть `WBP_Inventory` в Designer; изменить сетку и карточку. Стенд показывает пустую и полную сумку на нескольких размерах экрана.
5. Открыть MetaSound, прослушать и изменить параметр. Проверить пространственное поведение источника в `L_Preview_Audio`.
6. Изменить ручной ориентир и обновить PCG. Ориентир и авторские компоненты остаются на месте; меняется только генерируемая часть.
7. Play → выйти → Play: не растёт число подписок и звуков, preview не меняет пользовательское сохранение.

Обязательные будущие стенды: `L_Preview_Player`, `L_Preview_Stations`, `L_Preview_UI`, `L_Preview_Audio`, `L_Preview_Environment`, `L_Test_SessionFlow`, `L_Test_WorldTransition`. Каждый использует рабочие компоненты с отдельными тестовыми данными. Для открытия модели или настройки света прохождение сюжета не требуется.

Следующий этап — создать этот каркас и несколько проверочных композиций с временными ресурсами. Полноценный лагерь, правила проявления лаборатории и массовое наполнение миров к этому этапу не относятся.
