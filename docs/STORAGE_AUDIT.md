# Altai — аудит хранения

Дата: 2026-09-08. Проверка файловой системы и Git без удаления файлов, изменения индекса, переноса исходников или публикации. Размеры округлены; файловая система и сумма логических размеров могут немного отличаться. Это объём разработки, не размер упакованной игры.

## Текущее состояние

| Каталог | Размер | Решение |
|---|---:|---|
| Весь Altai | около 4,0 ГиБ | Основной рост сейчас связан со сборкой и Git |
| Intermediate | 1,6 ГиБ | Восстанавливаемая сборка; очищать при необходимости при закрытом редакторе |
| .git | 1,12 ГиБ | Уже добавленные обычные Git-объекты; не удалять вручную |
| Content | 659 МиБ | Версионировать через LFS; удаление ассетов только после проверки ссылок |
| SourceArt | 544 МиБ | Выделить тяжёлые внешние исходники из повседневной рабочей копии |
| docs/Images | 52 МиБ, 47 файлов | Отобрать постоянные иллюстрации; остальные перенести в отчёты проверки |
| Saved | 16 МиБ | Смешанные данные: сохранения, резервные копии, логи, снимки; не чистить целиком |
| Saved/Screenshots | 3 МиБ | Небольшой объём; сохранить опубликованные ссылки |
| Binaries | 3,1 МиБ | Собственные модули восстанавливаются сборкой |
| DerivedDataCache внутри проекта | 1,8 МиБ | Не отражает основной общий кэш Unreal |

Вне проекта: общий Zen/Data — около 1,9 ГиБ; общий DerivedDataCache — 639 МиБ в `~/Library/Application Support/Epic/UnrealEngine/Common`. Это общий кэш установки; нельзя целиком приписать его Altai. `/tmp/altai-tools` — около 6,6 МиБ, включая скрипты и резервные копии, а не только изображения.

## Git: наиболее срочное

- Репозиторий уже инициализирован, но HEAD/первого коммита ещё нет; remote не настроен.
- На момент снимка: 853 новых подготовленных файла, ещё 2 подготовленных файла имеют последующие изменения, 3 неподготовленных новых пути. В индексе 855 файлов. Сохранять различие между подготовленной и рабочей версиями при настройке.
- Git LFS 3.8.0 установлен; `.gitattributes` отсутствует, LFS-файлов нет.
- В индекс попали 34 файла Python-кэша. Существующий `.gitignore` исключает основные каталоги Unreal, но не `__pycache__` и `.pyc`.
- Git уже содержит 1149 свободно хранящихся объектов, около 1,12 ГиБ. Это не история готовых коммитов и не доказательство ненужности объектов.

Рекомендация: оставить Git, подключить LFS до первого коммита. Переписывать историю пока не требуется. Сначала сохранить индекс и различия подготовленных/рабочих версий; затем настроить LFS, убрать только кэш из индекса без удаления локальных файлов и перевести целевые бинарные файлы в LFS. Проверить содержимое будущего первого коммита, прежде чем создавать его. Не выполнять общий reset/повторное добавление поверх частично подготовленной работы.

LFS не сжимает модели и не гарантирует уменьшения текущего диска: рабочие файлы и локальное хранилище LFS занимают место, а прежние обычные объекты Git не исчезнут автоматически. Не запускать `prune --expire now` для быстрой экономии.

Предлагаемые дополнения к исключениям (не применены):

```gitignore
__pycache__/
*.py[cod]
.pytest_cache/
.mypy_cache/
.ruff_cache/
.venv/
/Saved/
/Intermediate/
/DerivedDataCache/
/Binaries/
/Plugins/**/Intermediate/
/Plugins/**/DerivedDataCache/
```

Существующие исключения IDE/macOS сохранить. Не исключать все `*.obj`: в SourceArt это модели. Не исключать все `*.bin`: это могут быть данные glTF. Не исключать `Content/__ExternalActors__`, `Content/__ExternalObjects__`, карты, построенные данные освещения и каталог Build. Для будущих плагинов без исходников отдельно сохранять поставляемые Binaries: существующее правило `Binaries/` слишком широко для такого случая.

Начальные правила `.gitattributes` для игрового репозитория (не применены):

```gitattributes
*.uasset filter=lfs diff=lfs merge=lfs -text
*.umap filter=lfs diff=lfs merge=lfs -text
/SourceArt/** filter=lfs diff=lfs merge=lfs -text
/SourceArt/**/*.py -filter -diff -merge text
/SourceArt/**/*.md -filter -diff -merge text
/SourceArt/**/*.json -filter -diff -merge text
/SourceArt/**/*.txt -filter -diff -merge text
/docs/Images/** filter=lfs diff=lfs merge=lfs -text
```

SourceArt предлагается временно сохранить в проекте под LFS до отдельной миграции. Код, метаданные, лицензии и генераторы должны оставаться обычным текстом. На стадии внедрения проверить правила `git check-attr` на реальных файлах. Хостинг Git/LFS и резервное копирование пока не выбраны; локальный Git сам по себе не является внешней резервной копией.

## Художественные исходники

Авторские `.blend`, `.spp`, `.ztl`, `.psd`, `.kra`, `.ma`, `.max` в SourceArt не обнаружены. Основной объём — импортируемые модели и текстуры:

- Environment/PolyHaven: 496 МиБ.
- Набор fir_tree_01: 288 МиБ, в том числе FBX 237,8 МиБ.
- InteractionAssets: 41 МиБ, из них Prepared — около 15 МиБ.
- Небольшие собственные генераторы, UI и лицензии выгодно оставить рядом с кодом.
- Побайтовых дубликатов файлов больше 1 МиБ между Content, SourceArt и docs не обнаружено. Исходник и импортированный uasset — разные представления, а не точные дубликаты.

Предлагаемая структура после отдельной миграции:

```text
Unreal/
  Altai/                       # код, Content, Config, docs, небольшие SourceArt/UI
  Altai-ArtSource/              # отдельное версионируемое хранилище
    Originals/Environment/     # исходные скачанные/авторские файлы
    Exports/Environment/       # версии, подготовленные для импорта
    Manifests/                 # лицензия, URL, SHA-256, параметры экспорта
```

В игровом проекте хранить манифест связи: ID ассета, путь пакета Unreal, путь исходника относительно хранилища, версия/хэш исходника, параметры подготовки. Для экспорта сохранять точную версию, использованную при импорте; возможность снова скачать файл по URL не заменяет архив и резервную копию.

Сейчас скрипты импорта и генераторы прямо используют `SourceArt/Environment`. Простое перемещение сломает повторный импорт/авторинг. Миграция должна включать единый resolver корня художественных данных (например, локальный ALTAI_ART_ROOT), адаптацию скриптов и путей AssetImportData через редактор, проверку повторного импорта на копии ассета. Для текстур сохранять связи с glTF и сопровождающими файлами. На другой машине игра должна собираться из Content без художественного архива; для переимпорта архив нужен.

## Кандидаты на сокращение Content

`fir_tree_01_a_LOD0.uasset` — 116,1 МиБ; `fir_tree_01_b_LOD0.uasset` — 62,7 МиБ. В THIRD_PARTY_ASSETS.md эти варианты указаны как исключённые из сцены. Вместе около 179 МиБ — приоритетные кандидаты для проверки Reference Viewer/Asset Registry, включая код, мягкие и строковые ссылки. Удаление не выполнено: MCP на localhost:8000 был недоступен, реальные зависимости не подтверждены. Текст документации не доказывает отсутствие ссылок во всех картах.

Не импортировать полные библиотеки в игровой проект без отбора. Для новых паков использовать отдельный библиотечный проект и переносить выбранные ассеты с зависимостями через Unreal Migrate.

## Порядок внедрения

1. Сохранить текущее состояние индекса и рабочие изменения; настроить исключения и LFS до первого коммита.
2. Проверить первый коммит и подключить выбранное удалённое хранилище с резервным копированием.
3. Проверить ссылки на тяжёлые варианты дерева через MCP; решить, что остаётся в игровом Content.
4. Отдельно перенести художественный архив вместе с адаптацией путей импорта и манифестом.
5. Ввести политику снимков: промежуточные — удалять после задачи; несколько финальных — сохранять с отчётом. Снимки, на которые ссылаются документы, не удалять без обновления ссылок.
6. Чистить Intermediate только при потребности в месте. Потенциально возвращает около 1,6 ГиБ сейчас, но сборка создаст его снова. Перенос 544 МиБ исходников на соседнюю папку того же диска не освобождает диск; экономия возникает при хранении архива на другом носителе и выборочной загрузке.
